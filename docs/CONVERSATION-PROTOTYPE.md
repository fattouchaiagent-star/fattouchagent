# FATTOUCH AI — Prototype المحادثة الأساسية

## الحالة

الإصدار الأول من مواصفات الـ Wireframe قبل بناء واجهة فعلية.

## القرار

المحادثة هي المنتج الأساسي. كل شيء يحدث داخل الخيط نفسه، مع لوحات وبطاقات مساعدة لا تقطع سياق المستخدم.

---

## 1. تخطيط سطح المكتب

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ FATTOUCH AI                         حالة الخصوصية   مشاركة   الحساب         │
├───────────────┬───────────────────────────────────────┬─────────────────────┤
│               │                                       │                     │
│ + محادثة جديدة│             خيط المحادثة              │  لوحة التفاصيل      │
│               │                                       │  (اختيارية)         │
│ اليوم         │  رسالة المستخدم                       │                     │
│  • محادثة 1   │                                       │  المصادر            │
│  • محادثة 2   │  رد FATTOUCH AI                       │  أو الملف            │
│               │                                       │  أو تقدم المهمة      │
│ سابقًا        │  بطاقة بحث / نتيجة / موافقة           │                     │
│  • محادثة 3   │                                       │                     │
│               │                                       │                     │
│ الإعدادات     ├───────────────────────────────────────┤                     │
│ الملفات       │  + إرفاق   اكتب رسالتك...        ↑    │                     │
└───────────────┴───────────────────────────────────────┴─────────────────────┘
```

### القياسات المبدئية

- القائمة اليسرى: 260px، قابلة للطي.
- الخيط: عرض قراءة 720–800px، متمركز.
- لوحة التفاصيل: 360px، مخفية افتراضيًا.
- حقل الرسالة: ثابت أسفل الخيط.
- الهاتف: إخفاء القائمتين وتحويلهما إلى طبقات منسدلة.

## 2. الحالة الأولى: لا توجد محادثة

العناصر:

- شعار FATTOUCH AI.
- عنوان: "كيف يمكنني مساعدتك في لبنان؟"
- وصف: "ابحث، حلّل، خطّط، وأنجز من خلال محادثة واحدة."
- حقل إدخال كبير.
- زر إرفاق.
- اختصارات:
  - حلّل سيرتي الذاتية.
  - ابحث عن وظيفة في لبنان.
  - خطط لي رحلة داخل لبنان.
  - ابحث عن خدمة قريبة مني.
- ملاحظة خصوصية مختصرة قرب حقل الإدخال.

## 3. الحالة الثانية: رسالة عادية

### رسالة المستخدم

تظهر في فقاعة أو كتلة خفيفة بمحاذاة اليمين في RTL، مع:

- النص.
- الملفات المرفقة إن وجدت.
- وقت الإرسال.
- قائمة إجراءات: تعديل، نسخ، حذف.

### رد المساعد

يحتوي على:

1. جواب مباشر في البداية.
2. تفاصيل منظمة عند الحاجة.
3. مصادر قابلة للفتح إذا كانت المعلومة متغيرة.
4. اقتراحات متابعة كأزرار صغيرة داخل الخيط.

## 4. الحالة الثالثة: مهمة مركبة

عند طلب عمل يحتاج بحثًا أو تحليلًا، تظهر بطاقة:

```text
سأعمل على هذا الطلب عبر:

✓ فهم طلبك
○ تحليل الملف أو التفضيلات
○ البحث في المصادر
○ التحقق والمقارنة
○ عرض النتيجة

[ابدأ]  [عدّل الخطة]
```

بعد بدء التنفيذ تتحول البطاقة إلى حالة حيّة:

```text
جاري العمل...

✓ فهم الطلب
✓ قراءة السيرة الذاتية
● البحث في 8 مصادر وظائف
○ مطابقة النتائج
○ تجهيز التوصيات

[إيقاف المهمة]
```

لا تظهر سلسلة التفكير الداخلية؛ تظهر فقط الخطوات التشغيلية المفيدة للمستخدم.

## 5. الحالة الرابعة: تحليل السيرة الذاتية

داخل الخيط:

1. المستخدم يرفع الملف.
2. تظهر معاينة الملف واسم الملف وحجمه.
3. يظهر طلب موافقة تحليل الملف.
4. بعد الموافقة تظهر بطاقة استخراج:

```text
استخرجت من سيرتك الذاتية:

المجال       تطوير البرمجيات
الخبرة       4 سنوات
المهارات     React، Node.js، TypeScript
اللغات       العربية، الإنجليزية
الموقع       بيروت

[تعديل البيانات] [اعتماد والمتابعة]
```

5. تظهر نتائج الوظائف كبطاقات داخل الخيط.
6. كل بطاقة تحتوي:
   - الوظيفة والشركة.
   - المنطقة أو العمل عن بعد.
   - تاريخ الإعلان.
   - سبب الملاءمة.
   - المصدر.
   - أزرار: حفظ، تحسين CV، تجهيز التقديم.

## 6. الحالة الخامسة: نتائج البحث

كل نتيجة تكون قابلة للمسح البصري:

```text
Software Engineer — شركة مثال
بيروت · دوام كامل · نُشر منذ 3 أيام

الملاءمة: عالية
السبب: تطابق React وTypeScript مع خبرتك

المصدر: example.com       آخر تحقق: اليوم

[فتح المصدر] [تحسين سيرتي] [حفظ]
```

يظهر أعلى النتائج:

- عدد المصادر.
- عدد النتائج.
- وقت البحث.
- فلاتر المنطقة والخبرة والحداثة.
- تنبيه إذا كانت بعض البيانات غير مؤكدة.

## 7. الحالة السادسة: الموافقة على إجراء

```text
قبل أن أرسل طلب التقديم، راجع التالي:

الجهة: شركة مثال
المستلم: careers@example.com
المرفقات: CV-FATTOUCH.pdf
البيانات المشاركة: الاسم، البريد، الخبرة، السيرة الذاتية

لن يتم الإرسال قبل موافقتك.

[إرسال الطلب] [تعديل] [إلغاء]
```

زر الإرسال يجب أن يكون واضحًا ومختلفًا عن زر الإلغاء.

## 8. الحالة السابعة: المصادر

عند الضغط على "المصادر" تفتح لوحة جانبية دون مغادرة المحادثة:

- اسم المصدر.
- الرابط.
- نوع المصدر.
- تاريخ الوصول.
- المعلومة التي يدعمها.
- حالة المصدر: موثوق، ثانوي، غير متحقق.

## 9. الحالة الثامنة: الفشل

يجب أن تكون الرسالة عملية:

```text
لم أتمكن من الوصول إلى مصدر الوظائف الآن.

ما تم إنجازه: حللت سيرتك الذاتية.
ما لم يتم: تحديث نتائج الوظائف.

[إعادة المحاولة] [استخدم مصادر بديلة] [إنهاء المهمة]
```

لا تظهر رسالة تقنية مثل `500 Internal Server Error` للمستخدم العادي.

## 10. نظام التصميم المبدئي

### الاتجاه

- RTL افتراضي.
- LTR للإنجليزية والفرنسية عند الحاجة.
- تصميم قريب من Claude وChatGPT في الهدوء والمساحات البيضاء، مع هوية FATTOUCH AI الخاصة.

### المكونات

- Sidebar.
- ChatThread.
- MessageBubble.
- Composer.
- AttachmentChip.
- TaskPlanCard.
- ProgressCard.
- SourceCard.
- ResultCard.
- ApprovalCard.
- ErrorCard.
- DetailPanel.
- Toast.

### قواعد بصرية

- لا ازدحام في الشاشة الأولى.
- لا لوحات معلومات منفصلة في المسار الأساسي.
- استخدام الحالات والأيقونات والنص، وليس اللون وحده.
- الأزرار الأساسية قليلة وواضحة.
- النتيجة المهمة تظهر قبل التفاصيل.
- المصدر قريب من الادعاء الذي يدعمه.

## 11. سيناريو اختبار الـ Prototype

### السيناريو A

"أريد وظيفة Frontend في بيروت، وهذه سيرتي الذاتية."

يجب أن يفهم المستخدم:

- أن الملف تم استلامه.
- ما الذي سيحلله النظام.
- أين ستظهر الوظائف.
- أن الإرسال يحتاج موافقته.

### السيناريو B

"خطط لي رحلة إلى الأرز لمدة يومين بميزانية 300 دولار."

يجب أن يفهم المستخدم:

- ما المعلومات الناقصة.
- ما المصادر المستخدمة.
- الفرق بين السعر المؤكد والتقديري.
- كيف يعدل الخطة داخل نفس المحادثة.

### السيناريو C

"أين توجد أقرب صيدلية مفتوحة في الحمرا؟"

يجب أن يفهم المستخدم:

- الموقع الذي استخدمه النظام.
- وقت آخر تحقق.
- أن ساعات العمل قابلة للتغير.

## 12. معيار اعتماد التصميم

لا يعتمد الـ Prototype قبل أن يستطيع 5 مستخدمين جدد تنفيذ السيناريوهات الثلاثة دون شرح شفهي، وأن يفهموا بوضوح:

- أين يبدأون.
- ما الذي يفعله النظام.
- من أين جاءت المعلومات.
- متى يطلب النظام الموافقة.
- كيف يعودون إلى المحادثات السابقة.

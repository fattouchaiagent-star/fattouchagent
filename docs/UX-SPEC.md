# FATTOUCH AI — مواصفات تجربة المستخدم

## 1. مبادئ الواجهة

- واجهة عربية RTL افتراضيًا.
- تبديل اللغة دون فقدان المحادثة.
- تصميم هادئ يركز على النتيجة.
- إظهار التقدم دون كشف سلسلة التفكير الداخلية.
- كل ادعاء متغير قابل لفتح مصدره.
- لا توجد أزرار تنفيذ حساسة بصياغة مبهمة.

## 2. التصميم الأساسي: Conversation-First

التجربة قريبة من Claude وChatGPT في بساطتها، لكن مع طبقة محلية وتنفيذية خاصة بـ FATTOUCH AI.

- المحادثة هي الشاشة الأساسية والمنتج الرئيسي.
- كل شيء يحدث داخل الخيط: الأسئلة، البحث، تحليل الملفات، النتائج، الموافقات، والتنفيذ.
- لا يتم نقل المستخدم إلى صفحة منفصلة لإنجاز وظيفة أساسية.
- التفاصيل الكبيرة تفتح في بطاقة موسعة أو لوحة جانبية مع بقاء الخيط ظاهرًا.
- لا نعرض سلسلة التفكير الداخلية؛ نعرض مراحل العمل والأدوات والمصادر والنتائج القابلة للتحقق.

### الصفحة الرئيسية قبل أول رسالة

- مساحة محادثة مركزية واسعة.
- شعار FATTOUCH AI ووصف قصير.
- حقل إدخال واحد واضح في أسفل المساحة.
- اختصارات داخلية: وظيفة، سياحة، تحليل ملف، بحث محلي.
- سحب وإفلات الملفات داخل حقل الإدخال.
- أمثلة طلبات لبنانية قابلة للنقر.
- لا لوحة تحكم مزدحمة قبل بدء الاستخدام.

### شاشة المحادثة الرئيسية

- شريط علوي بسيط: اسم المحادثة، مشاركة، إعدادات، وحالة الخصوصية.
- قائمة محادثات قابلة للطي على اليسار في سطح المكتب.
- الخيط في الوسط بعرض قراءة مريح.
- لوحة تفاصيل اختيارية على اليمين للمصادر أو الملف أو المهمة.
- حقل إدخال ثابت أسفل الخيط.
- رسائل المستخدم والمساعد مع دعم Markdown والجداول والملفات.
- البث التدريجي للرد مع زر إيقاف واضح.
- بطاقة خطة العمل قبل المهمة المركبة.
- بطاقات النتائج والمصادر والموافقة داخل الخيط.
- أزرار إعادة المحاولة والتعديل والنسخ والإبلاغ.

### الرسالة المركبة

تتكون من:

1. ملخص قصير للطلب.
2. حالة المهمة الحالية.
3. نتيجة قابلة للقراءة.
4. الأدلة والمصادر القابلة للفتح.
5. الإجراءات التالية.

### التنقل

- في الهاتف: الخيط كامل الشاشة، والقائمة واللوحات كطبقات منسدلة.
- في سطح المكتب: شريط محادثات يسار، خيط مركزي، تفاصيل يمين عند الحاجة.
- العودة من اللوحة الجانبية لا تنشئ سياقًا جديدًا.
- كل إجراء يحافظ على موضع المستخدم داخل المحادثة.

### بطاقة تقدم المهمة

تظهر الخطوات مثل:

- فهم الطلب ✓
- تحليل الملف ✓
- البحث في 12 مصدرًا ✓
- مطابقة 47 نتيجة ✓
- التحقق من الحداثة ●
- انتظار موافقة المستخدم

لكل خطوة: الحالة، الزمن، عدد النتائج، والأدوات المستخدمة بصورة مفهومة.

### صفحة النتائج

- ملخص تنفيذي في الأعلى.
- النتائج مرتبة مع سبب الترتيب.
- المصدر، تاريخ الوصول، وتاريخ الإعلان إن وجد.
- مرشحات حسب المنطقة، الميزانية، اللغة، النوع، والحداثة.
- إجراءات تالية واضحة.

### مركز الملفات

- قائمة الملفات.
- نوع الملف وحجمه وتاريخ الرفع.
- الغرض المستخدم فيه.
- مدة الاحتفاظ.
- تنزيل وحذف نهائي.
- حالة مشاركة الملف.

### الإعدادات والخصوصية

- اللغة واللهجة المفضلة.
- المدينة والملف المهني.
- مصادر مسموحة أو محظورة.
- الموافقات النشطة.
- سجل النشاط.
- تصدير البيانات وحذف الحساب.

## 3. لغة المنتج

استخدم عبارات مثل:

- "بحثت في المصادر التالية"
- "وجدت 8 نتائج قابلة للمطابقة"
- "هذه المعلومة تحتاج تحققًا مباشرًا"
- "لن أرسل الطلب قبل موافقتك"
- "لم أجد مصدرًا موثوقًا يكفي للجزم"

تجنب:

- "تم التأكد" إذا كان التحقق جزئيًا.
- "أضمن لك".
- "أرسلت" قبل نجاح العملية فعليًا.
- نسب دقة بلا تفسير.

## 4. نموذج الموافقة

قبل إجراء خارجي يجب عرض:

- الإجراء المقترح.
- الجهة المستلمة.
- البيانات التي ستُشارك.
- النتيجة المتوقعة.
- أي تكلفة أو أثر لا يمكن التراجع عنه.
- زر تأكيد واضح وزر إلغاء.

## 5. الوصولية

- تباين مناسب.
- دعم لوحة المفاتيح وقارئات الشاشة.
- نص بديل للملفات والصور.
- حالات تحميل لا تعتمد على اللون فقط.
- دعم الخط العربي بأحجام قابلة للزيادة.
- رسائل خطأ قابلة للفهم والتنفيذ.

## 6. متطلبات الأداء المرئي

- ظهور تأكيد استلام الطلب بسرعة.
- عرض التقدم في المهام الطويلة بدل شاشة فارغة.
- دعم إيقاف المهمة.
- حفظ النتائج الجزئية عند انقطاع الاتصال.
- عدم فقدان الملف أو الرسالة عند تحديث الصفحة.
